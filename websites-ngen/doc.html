Requirements

  • Python 2.3.2, to run wrapup.py (use earlier versions at your own risk)
  • Perl 5.6.1, to run Markdown (ActivePerl works fine)
  • Apache 2, to check your changes
  • Markdown 1.0b4 (included)
  • A UTF-8-capable text editor, such as Notepad (on Windows NT, 2000, and XP), TextEdit (on OS X), or Vim (on Windows NT/2000/XP, OS X, and most UNIX workalikes) when compiled with multibyte support

Usage

Simply run wrapup.py from its directory; make.bat and the Makefile will also do this. If nothing failed, you should see a newly generated .html file for every .markdown file that isn’t in the news directory.

Creating

Suppose you want to create a new document. Here’s how:

  1. Think of a good location to put it and what to call it. Don’t gloss over this step; what you write will—ideally—be available at that location forever.
  2. Create a directory for that location.
  3. Create and edit a file called index.markdown in that directory. You may want to keep an eye on the Markdown Syntax page.
  4. When you want to see your edits, run wrapup.py from its directory.

Apache Setup

If you want to view your changes on your own computer, you’ll need to install Apache 2. In either the <Directory> or the <VirtualHost> blocks, put the following directives: 

    Options Indexes Includes FollowSymLinks
    AllowOverride All

Ensure that mod_rewrite is on. The non-English versions of the site won’t work without it.

.inherit and .include files

Inherit and include files serve very similar purposes—they both reduce the amount of boilerplate that has to be typed in. Wrapup has five insertion points:

  1. Inside the head element
    (inhead.inherit and inhead.include)
  2. A CSS-specific inside-the-head element
    (css.inherit and css.include)
  3. Before the main content div, suitable for menus
    (beforecontent.inherit and beforecontent.include)
  4. After the text inside the main content div
    (aftermaintext.inherit and aftermaintext.include)
  5. After the main content div
    (aftercontent.inherit and aftercontent.include)

.include files provide a way to insert content into the above locations in the generated HTML document. .inherit files do that too, but they also will be included in sub-pages. For example, /speex/beforecontent.inherit will be added into both /speex/index.html and /speex/compare/index.html.

Multilingual Concerns

Non-English languages are handled by duplicating everything, but with a language-specific infix. For example, the Spanish-language counterpart to /index.markdown is /index.es.markdown. Similar additions exist for .inherit and .include files, such as css.ko.inherit.

If you’re the first person to translate a page from English, you’ll need to edit a lang.include file that has a |-separated list of all the available languages for that page. If you don’t know what it’s supposed to look like, see /lang.include for an example.

To refer to these pages from a Web browser, refer to, say, /speex/ja for the Japanese version of /speex/; the little bit of mod_rewrite translates that into the index.ja.html file that’s stored on disk.

If you’re adding a new language to the website for the first time, be sure to add it to the list of languages in /.htaccess so mod_rewrite will try to serve up your files.
