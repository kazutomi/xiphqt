Wrapup Documentation

Requirements

  • Python 2.3.2, to run wrapup.py (use earlier versions at your own risk)
  • Perl 5.6.1, to run Markdown (ActivePerl works fine)
  • Apache 2, to check your changes
  • Markdown 1.0b4 (included)

Usage

Simply run wrapup.py in the directory it’s in. If nothing failed, you should see a newly generated .html file for every .markdown file that isn’t in the news directory.

Creating

Suppose you want to create a new document. Here’s how:

  1. Think of a good location to put it and what to call it. Don’t gloss over this step; what you write will, ideally, be available at that location forever.
  2. Create a directory for that location.
  3. Create and edit a file called “index.markdown” in that directory.
  4. When you want to see your edits, run wrapup.py from its directory.

Apache Setup

If you want to view your changes on your own computer, you’ll need to install Apache. In either the <Directory> or the <VirtualHost> blocks, put the following directives: 


    Options Indexes Includes FollowSymLinks
    AllowOverride All

Ensure that mod_rewrite is on. The non-English versions of the site won’t work without it.

.inherit and .include files

Inherit and include files serve very similar purposes—they both reduce the amount of boilerplate that has to be typed in. Wrapup has five insertion points:

  1. Inside the head element
    (inhead.inherit and inhead.include)
  2. A CSS-specific inside-the-head element
    (css.inherit and css.include)
  3. Before the main content div, suitable for menus
    (beforecontent.inherit and beforecontent.include)
  4. After the text inside the main content div
    (aftermaintext.inherit and aftermaintext.include)
  5. After the main content div
    (aftercontent.inherit and aftercontent.include)

Inherited files came first when I developed Wrapup; I then realized that there would be many things that I would want on the front page but not on its subpages. I then implemented .include files for uninherited, page-specific things.

Multilingual Concerns

…index.es.html…/es…

After working with wrapup and adding ways for multiple languages to be added without too much fuss, I discovered that I’d need to have ways for non-English languages to override my CSS includes as Verdana is a poor first choice for text in Korean. Additionally, other languages like German may need tweaked widths to cope with its exceptionally long words. Further, each language would need its own sidebar include and perhaps its own header includes.

Given these constraints, each .inherit and .include set has language-specific infixes, such as css.es.include and aftermaintext.ko.inherit.
