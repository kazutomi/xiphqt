1.2. Jean-Marc Valin

Jean-Marc is getting very close to the Speex beta4 release. Recent additions to the CVS repository include code for:

  • VAD with bitrate reduction in VBR and comfort noise generation in CBR

  • Initial ABR support

  • Initial high-band perceptual enhancement

  • Quality improvements in the 2.15kbps mode

Jean-Marc also started a thread on the speex-dev mailing list soliciting feature requests for Speex 1.0. Beta4 will be the last beta release before the big 1.0, so if there's anything you'd like to see in Speex 1.0 that's not on the list of planned features on speex.org, feel free to let Jean-Marc know about it.

2. Interesting Discussions

2.1. Corrupted Ogg Vorbis Files

Christopher Verdesi asked the list in this message about a bunch of Ogg Vorbis files that were created by OggdropXPd v. 1.1., tagged with Winamp 2.80, copied over to Mac OS, and then copied back to Windows. Something in this process corrupted those files, and he wanted to know what could have caused this corruption.

The exact cause has not been determined, or at least no final resolution has appeared on the mailing list, but it is instructive as a general troubleshooting guide to discuss the theories that have been offered in response.

  • ID3 tags

    Many Ogg Vorbis files are corrupted because some older programs insist on adding ID3 tags to every file under the sun and don't realize that this actually corrupts Ogg Vorbis files.

    While this explanation doesn't help Christopher (Winamp 2.80 is new enough to avoid the ID3 mistake), ID3 tags are indeed a very common cause for corrupt Ogg Vorbis files.

    An Ogg Vorbis file that's corrupted by an ID3 tag can be repaired by simply removing the ID3 tag.

  • EOL munging

    Binary files in general, and Ogg Vorbis files in particular, don't take kindly to the translation of End-Of-Line characters that's performed during the transfer of plain text files between incompatible platforms. ASCII mode FTP between Linux and Windows, for example, will almost certainly corrupt an Ogg Vorbis file. (Solution: Use binary mode FTP instead!)

    Another example is an HTTP transfer from a server that wrongly identifies .ogg files as plain text files to a Windows browser. The solution here is to tell the server explicitly that .ogg files are binary files (MIME type application/x-ogg) so it won't fall back to a text/plain default and serve scrambled Oggs.

    EOL munging is in general irreversible, so an Ogg Vorbis file with this kind of corruption is most likely beyond repair.

  • Misguided Resource Fork

    Peter Harris surmised that, since the transfer involved Mac OS, the transfer software may have added garbage to the beginning of the file. In such a case, the file can be repaired by deleting the extraneous data that precedes the actual beginning of the physical Ogg stream, which is marked by the the character sequence OggS.

    While the reference decoder can actually deal with this kind of corruption, this could conceivably be a problem with other decoder implementations.

    As a general rule, make sure that you use a transfer method that reproduces a bit-identical copy of the original file.

3. Recent Developments

3.1. Ogg Standard Drafts submitted to IETF

Silvia Pfeiffer informs us in this message that she and Linus Walleij have submitted Internet Drafts for the Ogg file format and the application/ogg MIME type to the IETF. They intend to get both drafts accepted as RFCs at the next IETF meeting in March 2003.

3.2. New Vorbis Related Software

During the past week, two new projects have been added to the software section of vorbis.com.

  • Pocket Tunes is a media player application for the Palm Tungsten T, that can, among other things, play Ogg Vorbis files.

  • Xmcd is a CD player program that now also supports CD ripping to Ogg Vorbis and other formats.
