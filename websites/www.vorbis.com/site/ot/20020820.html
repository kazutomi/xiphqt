1. Status Updates

1.1. Monty

Monty fixed some typos in the Vorbis specification discovered by Kenneth Arnold.

1.2. Michael Smith

Mike's been doing a lot of work on icecast and ices over the past 2 weeks. Thanks to a patch from Oddsock, the XML icecast server stats can now be transformed using an XSLT file (into, for example, a very pretty HTML file). An example XSLT file is included with the icecast source. Oddsock also contributed a Win32 port, including GUI, for icecast, which is now in the icecast/win32 directory in CVS. Icecast now will generate .m3u responses for existing streams. The .m3u filename is just the stream name with .m3u appended (/stream.ogg will appear in the playlist file /stream.ogg.m3u). Simple fileserving from icecast has also been added, including sending the MIME type of the file based upon the file extension. Various other fixes to icecast include proper client counting, closed memory leaks, and logging improvements.

Ices is now more tolerant of corrupt (or poorly constructed) Ogg streams and has better error handling. Metadata elements specified globally in the ices config file can now be overridden in each <instance>. Playlist entries can now be commented out using "#", as in many other programs. The combination of resampling and downmixing with live sources has now been fixed.

Libshout has been modified to use HTTP Basic authentication as its primary authentication mechanism. The old ice-password method is still supported, but deprecated in favor of HTTP Basic auth.

In vorbis-tools, Mike fixed ogginfo to detect when Ogg files have unset granulepos values and also fixed a typo in the oggenc usage message.

2. Interesting Discussions

2.1. Feedback on Ogg Speex file format

Jean-Marc Valin, the main author of the voice codec "Speex," posted a request for feedback on a proposal for storing Speex data inside of an Ogg bitstream. Michael Smith suggested that Speex use the same comment format as Vorbis rather than define a new format. Both Michael and Ingo Blum noted that there was no need to have a special end-of-stream packet since Ogg packets already have an EOS flag. There was some confusion about what the granulepos value of an Ogg page meant, but Michael pointed out that granulepos is the last sample decodable from the current page.

Michael also mentioned in this thread that Segher's rehuff tool tended to produce mangled streams where every page had a granulepos of -1. Segher agreed, conceding that he had forgotten to set the granulepos in the Ogg pages. (Some of Michael's patches mentioned above are to allow more graceful handling of Ogg streams broken in this very manner.) Mike warned that vorbisfile could get stuck in an infinite loop if you tried to seek in a stream with all -1 granulepos values, but running the stream through vorbiscomment would fix this problem.

2.2. Chat with ogg

Olaf Marzocchi asked whether anyone had successfully used Ogg to do online voice chat. Several people pointed out that streaming voice from a live source is no problem with Vorbis, especially using ices and icecast. However, it was also noted that there would be quite a lag caused by all of the buffering present in the encode->send->decode path. It was suggested that Speex be looked at as an alternative to Vorbis that is more optimized for voice.

3. New Developments

3.1. IRC Channel Moved

The Vorbis discussion and development channel, #vorbis, has moved from the Openprojects.net IRC network to the new Xiph.org server at irc.vorbis.com. This server also hosts other Xiph.org related channels, like #icecast.

3.2. VP3 Patch for Xine

Mike Melanson posted instructions describing how to patch Xine to play VP3 (the video codec that will be used in Ogg Theora) files. It involves patching and compiling Xine from CVS, so it is definitely for the more experienced Linux hacker.

3.3. OggShell v1.0 released

Stefan Tobiasson announced that OggShell v1.0 had been released. As he describes it, "OggShell is a freeware Windows front-end for OggEnc. Suggestions and bug reports are welcome."

3.4. Support for Ogg Vorbis added to WebSiteRobot

Poly informed the vorbis list readers that support for encoding and publishing Ogg Vorbis files had been added to WebSiteRobot, a combined web page creation tool and server.

3.5. application/ogg status update

Linus Walleij has been working for quite a long time to make application/ogg an official MIME type. In his latest update, he informs us that the process has been stalled in the IETF working group by an objection that Ogg is not documented in an RFC. Linus says that he has been told that a reference implementation should be sufficient to satisfy the working group, but he is willing to write an Ogg RFC if they require one. He is requesting pointers to all known libraries that can manipulate Ogg files.
