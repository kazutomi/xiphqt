3.1. Vorbis 1.0

After a trip to Austin, I'm back this week with a new Ogg Traffic. This issue will cover the last two weeks of development. Congratulations to the Xiph.org team on Vorbis 1.0!

1. Status Updates

1.1. Monty

Monty finished off the Vorbis specification and put it into CVS (as well as the 1.0 release). In the process, he found and fixed some little remaining bugs in the Vorbis libraries. Testing also revealed a severe bug with the code that allowed you to set bitrate limits (accessed in oggenc with the -m and -M options). This was fortunately fixed before Vorbis 1.0 was released. Monty took a much deserved break after Vorbis 1.0 was officially released on July 19.

1.2. Michael Smith

Michael fixed some Borland compiler issues and fixed oggenc to not include Vorbis header packets in the bitrate displayed when compression is finished. Including the headers would tend to misleadingly inflate the bitrate display, especially on very short files. He updated ogg123 to display the new long form Replay Gain tags (REPLAYGAIN_* rather than RG_*). The -R (raw output) option in oggdec was changed to not have a binary flag value after it. Now, -R just means "output raw, headerless audio data". After the 1.0 release, Michael updated libvorbis in CVS to work around a qsort() bug on Solaris.

1.3. Chris Cheney

Chris made a quick fix to ogg123 adding support for HTTP redirection when loading Ogg Vorbis files from a URL. Chris also finished off the Debian package updates and uploaded the new Vorbis .debs into the Debian system when 1.0 was released.

1.4. Ralph Giles

Ralph fixed various documentation typos and committed a patch from David Gasaway to make it easier to link vorbis-tools code into C++ projects.

1.5. Andrew Chatham

Andrew updated the comment interfaces in the Python bindings. Comments can now be made using Python dictionary objects, which Andrew says is a big improvement. Andrew also updated the Python bindings to reflect the Vorbis 1.0 release.

1.6. Ryan Gordon

Ryan provided us with some much needed building assistance on Vorbis 1.0. He fixed some build issues on various platforms (like BeOS) and compiled many of the Vorbis 1.0 packages available for download on the Vorbis website. Special thanks go out to Ryan for helping us out!

2. Interesting Discussions

2.1. Quality and Ripping speed

Amy Schoenhofen asked about the ripping (and encoding) speeds people were getting with Vorbis 1.0. The thread quickly shifted to the question of the connection between quality level and ripping speed. Several people reported that the higher the quality level, the quicker the compression. However, Moritz Grim reported the opposite correlation. Shawn Leas actually performed a test and found that there wasn't much change in encoding speed at different quality settings on his system (others will certainly vary). At the end of his email, he gives the test scripts he used.

2.2. Ogg-on-a-Chip Project First Phase Finished

Pattara Kiatisevi announced that his group's masters thesis project to implement an Ogg Vorbis decoder in hardware had been completed. Details were available at the oggonachip website.

2.3. Ogg123 Crossfade

Nigel Weeks asked if it would be possible to add a feature to ogg123 allowing consecutive tracks to be cross-faded. This feature would allow one track to seamlessly fade into the next. Players like XMMS and Winamp have plugins that do this already. Stan replied that this would be difficult to implement in ogg123, but was open to suggestions. The discussion moved into the issue of how cross-fading should be done. Paul Martin pointed out that each song has a different optimal "end fade" point, so automatically doing a cross-fade is tricky. In this post he explains a little about his approach.

2.4. Rehuff for Ogg Vorbis

Segher Boessenkool posted an update of his rehuff tool to vorbis-dev. It is a tool you can run on Ogg Vorbis files that losslessly optimizes the compression in Ogg Vorbis files. It provides about a 3% reduction in size and shrinks the headers quite a bit.

3. New Developments

3.1. Vorbis 1.0

Of course, the biggest development this week (or year for that matter) is the release of Vorbis 1.0. Vorbis.com has a great listening test which we encourage everyone to try so you can see how great Vorbis is. For the statistically minded, ff123 conducted a group listening test of Vorbis, mp3pro, WMA8, and AAC in the 64 kbps region. Results have been posted for the test, showing mp3pro and Vorbis to be the winners.
