1. Status Updates

1.1. Michael Smith

Michael spent much of the week working on ices and icecast (audio streaming tools which support Ogg Vorbis). He has added support for resampling and downmixing both audio from live sources and audio from playlists. This should be a big help to those who want to create a broadband and a modem stream from the same source. He also fixed some bugs with using managed bitrates (like bitrate max and min) in ices.

2. Interesting Discussions

2.1. Rehuff for Ogg Vorbis

Segher's rehuff tool generated several questions on the vorbis-dev list. Most were curious what it actually did to increase the compression. Segher explained that it takes the Huffman codes used in the Ogg Vorbis file and replaces them with the optimal Huffman codes. (Huffman compression is explained a little bit here.) Christian Buchner asked why the Vorbis 1.0 encoding libraries did not do this sort of optimization automatically. Segher said that calculating optimal Huffman codes required you to know all of the data you were compressing (in the particular file) in advance. That would make the encoder a multipass encoder, which is no good for encoding a stream (which you transmit as you encode).

Several bugs in rehuff were found by various people on the list, so Segher posted a patch that fixed the reported problems. R. L. Horn reported that rehuff failed on single channel Ogg files. Segher confirmed that this was the case because he had not yet added support for mono files yet. (The current Vorbis encoder uses a different schemes to encode mono files and stereo files.)

2.2. General Purpose Decoder Chip

Tone announced that Cirrus was releasing a chip, the CS7410, that had both a DSP and a general purpose CPU core for decoding various audio formats, including MP3 and WMA. He and others discussed the possibility of using such a chip for Vorbis decoding. Kenneth Arnold posted links to the actual Cirrus pages documenting the chip in his post.

3. New Developments

3.1. Xiph.org Server Migration

The various Xiph.org websites were moved on August 6th to a new server with much more bandwidth. This new server was actually used during the Vorbis 1.0 release to serve images and the Vorbis packages. Now the websites are entirely being entirely served from the high bandwidth connection. Unfortunately, there have been some DNS issues with the registrar which might make the sites (which include xiph.org, vorbis.com and icecast.org) temporarily unavailable for some people, as Monty explained in a posting this morning. Special thanks go out to Greg Maxwell for providing Xiph.org with a new home.
