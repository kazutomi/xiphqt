1. Interesting Discussions

1.1. FUD-Busting

In this message, a reader invited the community to comment on the validity a few anti-Ogg claims that a friend of his made. The community reacted with a number of responses, the most noteworthy of which is this one by Monty, who takes the time to debunk the claims carefully and authoritatively.

Here is a summary of the claims, together with some responses.

  • Claim: Ogg has to this day, fundamental problems with low frequency encoding.

    Monty responds: "It did about two years ago. Since then, these claims have persisted, yet folks who claim it don't manage to pick it out in ABX testing (or pick out something unrelated)."

    The claim also mentions an artifact with the ominous sounding name of "pre-echo aliasing," but no definition to go along with it. The example that's given in place of a definition can be explained with interference between sound waves, as this response points out, and this phenomenon is an inherent property of sound that has nothing to do with whether you use Ogg Vorbis or not.

  • Claim: Ogg is not free from patents.

    Fact: Both Xiph.Org and AOL have conducted or commissioned patent searches by qualified patent attorneys who have determined that Ogg Vorbis is not infringing on any patents. Saying that Ogg Vorbis is not patent free without backing it up with a patent that Ogg Vorbis is infringing on, like the above claim does, is blatant FUD-mongering.

  • Claim: Ogg is too little, too late. Subclaim: Ogg should have gone with wavelets, like other audio and video encoding systems coming out in the next year.

    Response: Let's start out by noting that the claim is not providing any examples of this supposed next generation of wavelet based coding systems. Since the claimant offers no credentials apart from being a DJ, it is unlikely that he actually knows what a wavelet is, and more likely that he is just repeating buzzwords. As Moritz points out, the benefit from using wavelets for audio coding is far less than it's hyped up to be.

1.2. Recompressing Ogg Vorbis files

Olaf van der Spek reports in this message that bzip2 achieved a 10% reduction on a couple of Ogg Vorbis files, and he wonders how this can be.

John Morton explains that Ogg Vorbis uses pre-set Huffman codes in order to be able to encode the source in one pass. Encoding with optimal Huffman codes requires two passes, which would make live encoding and streaming impossible.

Because of the sub-optimal one pass method, it is possible to gain some space by recompressing an Ogg Vorbis file, but space savings as dramatic as 10% could not be reproduced with the current version of the encoder. (For example, a quick test by myself resulted in a pitiful 0.2% gain on a randomly chosen file from my collection.)

Segher Boessenkool is currently developing a tool that optimizes the Huffman codes for a given Ogg Vorbis file in order to shave off a few percent of the file size. He reports that the resulting space savings are normally under 5%, and typically between 1% and 2%.

2. Recent Developments

2.1. Using oggenc to convert FLAC to Ogg Vorbis

Remember this discussion about converting FLAC to Ogg Vorbis? Stan Seibert adds another solution to the problem: a patch to oggenc. This patch allows oggenc to read in a FLAC file as input file and copy metadata comments into the Ogg Vorbis output file.

There were build problems reported by one user, so as always, Your Mileage May Vary!
