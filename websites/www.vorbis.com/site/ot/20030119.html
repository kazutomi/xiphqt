So far it seems to be going well, but remember that this is only an evaluation phase, so don't run to the stores just yet.

Jean-Marc has released Speex Release Candidate 1. Read his announcement below.

Michael committed fixes to lots of miscellaneous bugs in icecast and the vorbis tools.

1.4. Brendan Cully

Brendan rejoined the icecast development team, and committed, among other things, lots of code cleanup and build fixes to icecast.

1.5. Stan Seibert

Stan went on a coding spree to turn oggenc and ogg123 into tools for more than just Vorbis. He continued work on his FLAC reader patch for oggenc, which will now read Ogg Flac files in addition to native Flac files, and the patch also now reportedly builds on Win32 systems. On the ogg123 side, he added playback for both Ogg Flac and Speex files.

Andrew, the maintainer of the Ogg Vorbis python modules, committed a patch that allows the modules to build on Windows.

2. Interesting Discussions

2.1. Playing Ogg Vorbis with Windows Media Player

This question was relayed to the icecast mailing list, asking how to play Ogg Vorbis files with Windows Media Player. Some people seem to believe that you need Winamp to play Ogg Vorbis on Windows, but that's not true. Monty points out that there's a DirectShow Ogg Vorbis filter listed on the Windows software page on vorbis.com that will allow Windows Media Player and any other DirectShow aware application to play Ogg Vorbis files.

2.2. Replacing Real Audio with Low Bitrate Ogg Vorbis

Derek Sivers from the independent music site CD Baby is dying to ditch their current RealAudio format in favor of Ogg Vorbis, and he asked the community in this message for help to come up with good settings for creating low bandwidth streams that are comparable in bitrate and quality to their current RealAudio streams.

In general, when you want to achieve a really low bitrate, you're going to have to go with a low --quality setting, downsampling, and possibly downmixing to mono. In addition, for streaming purposes, you should specify a maximum bitrate to prevent problems for the listeners with slow modems.

There will always be a certain trade-off involved when encoding to very low bitrates, so the settings vary depending on personal taste. Derek ultimately decided on oggenc -M 28 --downmix --resample 32000 -b 24.

We're hoping to see Derek introduce 30,000 musicians and 200,000 customers at CD Baby to the advantages of Ogg Vorbis. When CD Baby moves to Ogg Vorbis, or at least offers it as an alternative to RealAudio, you'll certainly read about it in another Ogg Traffic!

3. Recent Developments

3.1. Bugzilla updated

Xiph.Org's bug database at bugs.xiph.org has been updated to include the most recent versions of all Xiph products, and all maintainer email addresses have been updated.

If you encounter something that you think is a bug, please help the developers by submitting a bug report to bugs.xiph.org or mailing it to the developer list. Because of its bug-tracking capabilities, bugs.xiph.org is the preferred method for bug reports, but adding bug reports requires a user login, so casual reports to the mailing list are fine, too.

3.2. User confirms Ogg Vorbis Support in DVD Player

As a follow-up to the previous report about the KiSS DP-450 DVD Player, a user confirms in this message that the device indeed plays Ogg Vorbis files. The device reportedly has display problems with UTF-8 characters in tag data, and it calls it MP3 playback when playing Ogg Vorbis files, but the music plays just fine.

3.3. Speex RC1

Here is Jean-Marc's announcement of the Speex RC1 release:

 

This is Release Candidate 1 for Speex 1.0. The only new feature (yes, I know beta4 was supposed to be feature-complete) is a very low bitrate (3.95 kbps) mode for narrowband. This release also fixes a number of bugs, including a fix for low-bitrate wideband encoding--however, this fix adds high-frequency noise during the decoding of beta4 and earlier data. Finally, the WAV handling is more robust and handles undocumented extensions better.

The goal is to release RC2 in early February, and if all goes well (no major bugs are found), release 1.0 before March. For more details, including how you can make 1.0 better, see the Roadmap at www.speex.org/todo.html.

  
--Jean-Marc
