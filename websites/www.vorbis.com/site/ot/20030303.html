1. Status Updates

1.1. Monty

Monty has begun work on Neurosetta, the Vorbis-enabled firmware for the Neuros Digital Audio Computer. His progress will be documented on the upcoming Neurosetta web site.

He also found the time to code an extension to vorbisfile that will make it more useful for in-game music. Since vorbis is lossy, piecing together vorbis files can introduce tiny clicks at the boundary, even if the originals to the pieces fit together seamlessly. With the recently coded overlap functions, such operations can be performed seamlessly.

2. Interesting Discussions

2.1. Goals and non-Goals of Vorbis Comments

The topic of Vorbis comments is very similar to a volcano: It lies dormant for a long time, and then it suddenly erupts without warning into a lava flood of flaming mailing list traffic. Such an eruption was accidentally triggered by Sergey Meniailenko when he asked in this message how he can tag a Vorbis file with information that indicates a guest artist.

Vorbis comments are a delicate subject because they serve a very specific purpose, but some people want to use them for more than that. Vorbis comments store human-readable information that provides clues about the contents of the file. Vorbis comments are not designed to form the basis for an all-encompassing database of music metadata.

This distinction is apparently hard to grasp for many people. Vorbis comments are the equivalent of a quick note scribbled on the bottom of a CDR. They are not designed to store cover artwork, karaoke lyrics, or the artist's family tree.

When confronted with this shortcoming of vorbis comments, people naturally ask where they should store cover artwork, karaoke lyrics, or the artist's family tree. The answer is: It doesn't really matter. Nobody is going to stop you from storing a uuencoded PNG file in a vorbis comment for cover artwork, but such maneuvers only work for you. There is no standard for conveying cover artwork, so you can store it anyway you like, as long as you don't expect it to work anywhere outside your own PC. (If you give such a file to a friend whose player displays nonstandard tags verbatim, they'll simply get flooded with a deluge of uuencode nonsense.)

The lack of a standard for such arbitrary metadata is the core problem. Monty didn't think it was necessary to have such a standard, and since he created Vorbis, this decision was completely within his rights. Vorbis comments will never become a mechanism for storing arbitrary metadata.

If you want to store arbitrary metadata, make up a method for storing, retrieving, manipulating, and using arbitrary metadata. If enough people use this method, and if it doesn't use vorbis comments for data storage, it has a chance of becoming a standard.

Until that fine day, what do we tell Sergey about storing a guest artist's name in a vorbis file? Since there is no standard for a GUESTARTIST tag, the answer depends on what software Sergey has available, and on how the software displays nonstandard tags. He could store it in a GUESTARTIST tag. He could list the main performer and the guest performer in separate PERFORMER tags. There may be other solutions. The answer ultimately depends on which one works best for Sergey.
