2. Interesting Discussions

2.1. Converting FLAC to Ogg Vorbis

Randolph Carter asked in this message if there's an easy way to convert a FLAC encoded file to Ogg Vorbis without losing the metadata tags.

For Windows users, there is Oggifier, as this reply pointed out. Oggifier is basically a graphical frontend to oggenc that can transcode from various formats, including FLAC, and preserve metadata tags, so it fits the bill exactly, except that Randolph was interested in a Linux solution.

For Linux, at least for the command line, Josh Coalson suggested something along the lines of:

oggenc ... \ 
       -a `metaflac --show-vc-field=artist | sed '/^.*=//'` \ 
       -t ... \
       -l ...

Beni Cherniavsky responded that this "pull" style for metadata tagging drops anything that isn't explicitly listed in the encoding command. He suggested that it would be better to retrieve all tags and somehow feed them to the oggenc command, e.g. using xargs. The actual implementation is left as an exercise to the reader.

2.2. Transcoding Ogg Vorbis to Ogg Vorbis

As a follow-up to the transcoding discussions of the past, a reader wondered in this message how bad the quality loss from transcoding Ogg Vorbis to Ogg Vorbis would be in comparison to an MP3 to Ogg Vorbis transcoding.

Monty responded that the quality loss would probably not be quite as bad, but reencoding should be avoided if possible, since there will be generational loss in each reencoding.

Here is my layman's explanation for why quality loss will always happen during reencoding: Ogg Vorbis encoding is an approximation of whatever audio data is fed into it. This can be illustrated with the task of rounding a given number to a certain precision. For example, take the number 1.447, and round to two decimal places, and you get 1.45. Now "reencode" the result by rounding to one decimal place, and you get 1.5, even though the original would have been rounded to 1.4.

If you think this example is simplistic and contrived, you're right, but it still illustrates the problem of generational loss that's inherent in any reencoding process. Other examples include making an audio tape copy of an audio tape, a video tape copy of a video tape, a fax of a fax, etc.

2.3. Preaching the Gospel of the Fish

Corey Miller reported in this thread of his attempts to bring the goodness of Ogg Vorbis to more people. He hopes to convince The Massinova Project to provide Ogg Vorbis streams. The feedback on the Massinova User Forum about Ogg's quality has been very positive. While there is no indication of whether Massinova will actually provide Ogg Vorbis streams, Corey's advocacy has introduced Ogg Vorbis to a number of people that wouldn't have known about it otherwise.

3. Recent Developments

3.1. Speex Beta 4 Released

On December 20, 2002, Jean-Marc Valin released Speex Beta 4. Here is his announcement:

This is the 4th beta and probably the last before we start putting out release candidates. This release adds a number of quality improvements and some new features; first, the quality of the variable bitrate (VBR) mode has been greatly improved, especially for wideband. Also, some improvements were made to the packetloss concealment code in order to reduce artifacts caused by lost packets. There has been improvements to the 2.15 kbps mode, which now sounds a bit better. The last quality improvement is in the perceptual enhancement which is now good enough to be enabled by default in speexdec (but not by default in libspeex for now).

One of the new features in this release is a VAD (Voice Activity Detection) mode that conserves bandwidth when there's no speech, and even when VBR isn't enabled. VAD is coupled with DTX (Discontinuous Transmission), a feature that can completely stop data transmission when the noise is constant (in which case, comfort noise generation is turned on). The last new feature in this release is an ABR (Average Bitrate) option, which uses VBR with a quality that's adjusted to meet a certain target (average) bitrate.
